# Architecture Review
Generated: 2026-09-16T16:27:48.477Z
Score: 75/100

## Summary
The codebase is a well-documented App-in-Toss mini-app with consistent SPEC/packet annotations, a clean repo/service layering (flowRepo/runRepo/planRepo → services → pages), and reusable TDS wrapper components (Card, ScreenScaffold, StateView). The main weaknesses are a widespread copy-pasted haptic-feedback wrapper, a stale/duplicate 'contract.ts' type layer that has drifted from the real implementation and overlaps in name with src/types/*, and a real (type-only) circular import between lib/types.ts and api/contracts.ts. These are fixable without a rewrite.

## Issues
### Warnings
- [circular_dep] src/lib/types.ts does `export * from '@/api/contracts'`, while src/api/contracts.ts does `import type { Flow, FlowDraft, RunLog } from '@/lib/types'`. This is a direct A→B→A circular dependency between the barrel file and one of its own re-exported modules. It currently 'works' only because the import is type-only (erased at compile time); any future value-level import added to either file would create a real runtime cycle. — Files: src/lib/types.ts, src/api/contracts.ts / Fix: Have contracts.ts import Flow/FlowDraft/RunLog directly from their source modules (@/types/flow, @/types/run) instead of from the @/lib/types barrel, so the barrel only aggregates and is never imported by its own members.
- [duplication] The 'wrap generateHapticFeedback in try/catch because it throws outside the Toss WebView' pattern is independently reimplemented in at least 9 places with inconsistent signatures (some hardcode a fixed feedback type, others accept a type param): BottomCTA.tsx (fireHaptic), FloatingTabBar.tsx (inline), Home.tsx (fireHaptic), TemplateDetail.tsx (fireHaptic), Plan.tsx (fireSuccessHaptic), Builder.tsx (tick), ActionListSheet.tsx (tick), AiStepSheet.tsx (tick), TriggerInputSheet.tsx (tick). — Files: src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/pages/Home.tsx, src/pages/TemplateDetail.tsx, src/pages/Plan.tsx, src/pages/Builder.tsx, src/components/builder/ActionListSheet.tsx, src/components/builder/AiStepSheet.tsx, src/components/builder/TriggerInputSheet.tsx / Fix: Extract a single `src/lib/haptics.ts` exporting `fireHaptic(type: 'success' | 'error' | 'tickWeak' | ...)` that owns the try/catch + Promise.resolve(...).catch(), and have every caller import it instead of redefining a local wrapper.
- [structure] Two parallel type systems share names but not shapes: src/lib/contract.ts declares generic scaffolding types `Flow`, `Action`, `Trigger`, `Run` (e.g. `Action = { id, type, config, enabled }`) that no longer match the real domain types in src/types/flow.ts and src/types/run.ts (e.g. real `Action` is a discriminated union with no `id`/`config`/`enabled`). Production code imports `Flow`/`RunLog` from `@/lib/types`, while validateDraft.ts/validateDraft.test.ts/metrics.ts import a same-named but differently-shaped `Flow`/`Run` from `@/lib/contract`, which is confusing and risks accidental type mismatches at call sites. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/validateDraft.ts, src/lib/metrics.ts / Fix: Rename the contract.ts types to avoid collision (e.g. `ContractFlow`, `ContractAction`) as validateDraft.ts already does locally with `ContractFlow`, or retire contract.ts's entity types now that the real implementation types in src/types/*.ts exist, keeping contract.ts only for genuinely cross-packet function signatures that are still authoritative.
- [dead_code] src/lib/contract.ts exports several function-shape 'contract' types (getFlowFn, saveFlowFn, listFlowsFn, getRunFn, listRunsFn, subscribeToRunFn, validateFlowFn, useAppStateFn, apiClientFn) that are not used as type annotations by any implementation shown (flowRepo, runRepo, useAppState, apiClient, validateDraft all have signatures that no longer match these declarations, e.g. useAppStateFn's `{ user, plan: 'free'|'pro', setFlows }` vs the real `useAppState`'s `{ flows, runs, usage, plan: PlanState, isFree, consumeCorruption, refresh }`). These are stale artifacts from the original packet scaffold. — Files: src/lib/contract.ts, src/hooks/AppStateContext.tsx / Fix: Delete the unused Fn types or update them to match the shipped implementations so contract.ts stops documenting an API that no longer exists.

### Suggestions
- [duplication] `actionUrl(action)` (mapping slack_webhook/google_sheet_append to their URL field) is defined identically in two page files instead of a shared module. — Files: src/pages/FlowDetail.tsx, src/pages/TemplateDetail.tsx / Fix: Move actionUrl into src/lib/format.ts (which already owns other Action/Trigger formatting helpers) and import it from both pages.
- [duplication] KST datetime display formatting is reimplemented separately with slightly different options in three places, even though src/lib/time.ts already centralizes other KST logic (getKSTMonth, getKSTDayWindow). — Files: src/pages/RunDetail.tsx, src/pages/Runs.tsx, src/pages/FlowDetail.tsx / Fix: Add formatKSTDateTime/formatKSTShort helpers to src/lib/time.ts and have all three pages call the shared version.
- [dead_code] src/lib/storage.ts (getItem/setItem/removeItem) duplicates the responsibility of src/lib/safeStorage.ts + src/lib/repos/shared.ts, but none of the repos (flowRepo, runRepo, planRepo, usageRepo, clientRepo) or other shown files import from it — it appears to be an orphaned earlier version of the storage abstraction. — Files: src/lib/storage.ts, src/lib/safeStorage.ts, src/lib/repos/shared.ts / Fix: Delete src/lib/storage.ts if truly unused, or if it's kept intentionally for a non-repo use case, document why it coexists with safeStorage.ts/repos/shared.ts.
- [structure] Tests are organized under three different conventions simultaneously: co-located `*.test.tsx` next to source (App.test.tsx, RunDetail.test.tsx, builder.test.tsx, validateDraft.test.ts), a shared-helpers folder (src/__tests__/__helpers__/mocks, test-utils), and a separate top-level src/test/ folder for cross-cutting suites (adPlacement.test.tsx, policy.test.ts, setup.ts). — Files: src/App.test.tsx, src/test/adPlacement.test.tsx, src/test/policy.test.ts, src/pages/RunDetail.test.tsx / Fix: Pick one convention going forward (co-located tests are already the majority) and move src/test/*.test.tsx into co-located or a single clearly-named 'integration tests' directory so newcomers don't need to search two locations.
- [dead_code] `cn` and `formatCurrency` exported from src/lib/utils.ts are not referenced by any file in the provided codebase (styling uses inline style objects everywhere, and money display uses Amount/CountUp with formatNumber, not formatCurrency). — Files: src/lib/utils.ts / Fix: Confirm usage with a repo-wide grep; remove if genuinely unused, or keep only if intended for near-term use.
